# Web2D Review: Bugs, Typing, Performance, Legacy Patterns and Unit Tests

Review of `packages/web2d` (43 TypeScript files, 4,731 lines), carried out on 2026-10-04 against `develop` (`d36e1c12`). The review was read-only, so no source file was changed.

Unless noted otherwise, paths are relative to `packages/web2d/src/components/`. Paths that start with `mindplot:` are relative to `packages/mindplot/src/components/`.

Severity levels (the same as `MINDPLOT_REVIEW_PLAN.md`):

- **H**: user-visible data loss, a security problem, or a broken feature.
- **M**: incorrect behaviour that is narrower or easy to work around.
- **L**: cosmetic, latent, or cleanup.

Rows marked `*` are _likely_: the mechanism is confirmed, but the visible effect depends on runtime context. Every other row was confirmed by reading the code, and most were also reproduced in jsdom (see the Appendix). Item IDs (`W-…`) are for tracking.

No security issues were found. Text goes through `textContent`, and `<image href>` does not execute script.

## 5. Performance

Ordered by expected gain. The figures come from jsdom instrumentation (Appendix).

1. **Delete the change broadcast** (W-BROADCAST). Building a map is quadratic: 6.0 M visits for 1000 topic-like groups, and every zoom or `setCoordSize` visits every element. Deleting it is behaviour-neutral in SVG.
2. **Text redraw churn.** Each topic redraw (`mindplot:Topic.ts:1298-1340`) costs:
   - **17 `setAttribute` calls on unchanged values**, because each of `setColor`, `setFontSize`, `setWeight`, `setStyle` and `setFontName` rewrites all 4 font attributes.
   - A **new `FontPeer`** in every `setFontName` call.
   - **All tspans removed and recreated** even when the text is unchanged. Then `setPosition` rewrites every tspan's `x` through `querySelectorAll`.
   - **3 `getBBox` calls** (`getShapeWidth`, `getShapeHeight`, `getFontHeight`) interleaved with writes, so every topic forces a synchronous layout. A full redraw therefore costs O(n) layouts.

   Fixes:
   - Setters that detect changes (a per-element attribute cache, `attr(name, value)` that skips equal values).
   - Keep the `FontPeer` when the name is the same.
   - Rebuild tspans only when the text changes.
   - **A measurement cache** keyed on text + font, invalidated by `setText`/`setFont`, with one `getBBox` returning `{width, height, lineHeight}`.
   - In mindplot, a measure phase followed by an apply phase.

3. **Path rebuilds.** For curved connections, mindplot calls `setFrom`, `setTo`, `setSrcControlPoint` and `setDestControlPoint` in sequence. Each one regenerates `d`, so there are 4 path strings and 4 DOM writes per connection per redraw (`setFill` adds a 5th). Heartbeat and Neuron are the same. Fix: mark the path dirty and render once (an explicit `update()`, or a microtask flush).
4. **Pointless attribute writes.** `ElementPeer.setSize` writes `width`/`height` on elements where they mean nothing (`<g>`, `<text>`, `<path>`, `<line>`, `<polyline>`). `RectPeer` and `ElipsePeer` always rewrite `rx`/`ry`. `WorkspacePeer.setCoordSize` rewrites `preserveAspectRatio`. `setVisibility` always writes 1 attribute and 2 style properties, and mindplot's `Topic.setVisibility` calls it for every part of every topic on collapse or expand.
5. **Allocations per call.** The viewBox string is parsed and serialized on every pan event (getOrigin, setOrigin, plus coordSize reads); `baseVal` removes this. `NeuronLinePeer._rand` recomputes `_pseudoSeed()` (a `sin`) 6 times per step. The heartbeat pattern array is rebuilt on every call. There are 42 `toFixed` string conversions on hot paths.

## 6. Legacy practices and modern approaches

> **Decided (2026-10-04):**
>
> - **VML is dead.** Any code, logic or hack that exists only to support VML must be removed. This covers the `Toolkit` factory that chose the peer implementation, the change-event broadcast (`EventUtils`, `attachChangeEventListener`, `updateStrokeStyle`, `onChangeCoordSize`), VML-only attributes and doc comments, and any emulation of VML coordinate semantics that SVG `viewBox`/`transform` already provide.
> - **Keep the Element/Peer abstraction.** Elements stay the public API, and peers stay the SVG implementation behind them. The "collapse Element/Peer" step (M6/W4) is dropped. Peers keep being created directly (`new RectPeer()`, …) once `Toolkit` is gone.
> - Where a VML-era concept is still the public API that mindplot uses (e.g. `setCoordSize`/`setCoordOrigin` on `Workspace`/`Group`), keep the API and implement it natively on SVG. Only the VML-specific machinery behind it is removed.

Web2D started in about 2007 as a VML (IE ≤ 8) and SVG abstraction. VML was removed in 2022 (`37a84d35`), and jQuery and MooTools were removed in the 2021–22 TypeScript migration. The _structure_ those dependencies needed is still in place.

### 6.1 Recommended target architecture

```
web2d/src/
  geometry/      pure, no DOM: polyline variants, curved/tapered, arc, arrow, heartbeat, neuron,
                 default control points, chamfer; returns Point[] / path data; 100 % unit-tested
  dom/           svg(tag) factory; attr(el, name, value) with change cache; EventScope (AbortController,
                 on() -> unsubscribe, dispose()); measureText cache
  shapes/        Shape<E extends SVGGraphicsElement> base (node, stroke, fill, opacity, visibility,
                 z-order, events, dispose) + Rect, Ellipse, StraightLine, PolyLine, CurvedLine,
                 ArcLine, HeartbeatLine, NeuronLine, Arrow, Image, Text, Group (numeric transform),
                 Workspace (viewBox via baseVal, ResizeObserver, clientToWorld())
  types.ts       as-const unions (StrokeStyle, Orientation, PolyLineStyle, …), Readonly Position/Size,
                 StyleAttributes, Web2dEventMap, Line / ControlPointLine
  index.ts       same exported names; ElementClass = Shape alias; ElementPeer = deprecated type alias
```

Principles:

- One object per SVG node.
- No reflection.
- Every write goes through a cache that skips unchanged values.
- Geometry is pure.
- Listeners are always disposable.
- No global state.
- The public names mindplot imports today stay the same.

## Appendix: method

- **Coverage of the review.** All 43 files were read. Every public method was cross-referenced against `packages/mindplot/src` (call-site counts by name, then manual tracing for ambiguous names) to find dead APIs and the behaviours mindplot relies on.
- **Reproductions in jsdom.** Scratch Jest suites in the session scratchpad imported `web2d/src` directly through ts-jest, with a stub `getBBox`. The following were reproduced:
  - Events: W-EVTMAP.
  - Coordinates: W-VIEWBOX, W-HTMLFONT, W-GTRANSFORM, W-GDEFAULTS.
  - Geometry: W-VCURVE, W-HCURVE, W-MIDCURVE, W-DEFCP, W-TAPER, W-ARROWDASH, W-STALEPATH.
  - Styling: W-DASH, W-OPACITY, the `getFill` default, Rect rounding/NaN, the Liskov throws.
  - Text: `getFontHeight('')`, CRLF, `setFont` reset, tspan rebuild.
  - Attribute bag: W-ATTRBAG string leakage.
- **W-CTRLFLAG** was reproduced with a scratch test on mindplot's `test/unit/commands/designer-harness`: load a map, read the line's custom flags, move the target topic, and compare the control points' absolute positions.
- **Performance.** Broadcast visits were counted by wrapping `ElementPeer.prototype.getChangeEventListeners`, and attribute writes by wrapping `setAttribute` on the `<text>` node.
- **Typing.** Metrics come from `tsc --noEmit -p tsconfig.json` with each extra flag enabled one at a time, plus grep counts for `!`, `as`, `$assert` and `$defined`. ESLint was run with `npx eslint src`.
- **Indirect coverage.** mindplot's 91 unit suites (760 tests) were run with `collectCoverageFrom` pointed at `web2d/src`, using a scratch config whose `rootDir` was `packages/`.
- **Not run:** Storybook and Cypress, because other agents were using the ports. The rows marked `*` depend on runtime context (layout orientation, resize events, browser `getBBox` behaviour) and should be confirmed in Cypress when they are fixed.
